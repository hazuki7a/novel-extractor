# 给 Codex 的执行任务：建设离线 Benchmark

## 目标

将本目录的候选采集计划接入现有小说解析项目，建立可回放、可标注、可比较的测试流程。
本轮不实现机器学习、不加入云端 API、不批量下载整本小说，也不默认访问 20 个网站。

## 先确认，而不是假设

1. 阅读 `BENCHMARK_GUIDE.md`、`benchmark_sites.json` 与 templates。
2. 检查仓库已有的 Fetcher、Analyzer、Crawler、Cleaner、Exporter、数据模型及测试命令。
3. 先报告哪些能力已经存在、哪些只是规划；不能把过去的指导文档当作实现完成证明。
4. 尽量通过评测适配器统一已有返回值，不为了对齐模板大规模重写业务代码。
5. 没有具体网页快照时，不得将站点标为 supported 或测试通过。

## 按顺序完成

### D01 — 清单和标注合同

- 保留20个候选来源及核验状态。
- 定义输入模式：HTTP_BYTES / BROWSER_DOM / SYNTHETIC_HTML。
- 区分页面类型、访问状态、内容状态和是否需要 JS。
- 校验 READY 用例的文件、哈希、URL映射、标签和引用。
- DRAFT、待采集、尚未实现等状态单列，不作为成功。
- `templates/*.json` 是模板，不扫描为真实用例。

### D02 — 离线输入适配器

- 对 HTTP_BYTES 使用项目自己的字符解码流程，保留必要 HTTP 元信息。
- 对 BROWSER_DOM 明确为已经渲染的输入，不反推源站字节编码。
- 通过用例的 URL→快照映射回放导航、章节分页和目录分页。
- 禁止测试时偷偷访问网络；未保存目标要报告输入缺失/超出范围。
- GET可复用同一文档，但保留 #fragment 章节身份及必要query参数。
- 不把请求URL中所有数字都归一化，否则可能合并不同书籍/章节。

### D03 — 真实模块与评估器隔离

- 推断阶段只接触采集输入和正常请求元信息。
- 只有评估器能读取 expected.json、正文标签与人工XPath。
- 不将站点名称、测试场景或 gold selector 作为解析器提示。
- 解析输出可转成统一 prediction.json；保留原始诊断结果。

### D04 — 指标与错误分层

- 中文正文、访问状态、动态输入、外语、非HTML、自制样本分开统计。
- 正文缺失/污染、目录遗漏、顺序错误、分页错误、元数据错误分别记录。
- 报告分子、分母、样本数、按站点与按页面聚合。
- 分母为0显示N/A；已拒绝的正常正文算abstention，不算提取成功。
- 明确用例只覆盖局部章节时，不声称整本完整。
- 冷缓存和热缓存分开；保留代码commit、依赖、数据集与配置版本。

### D05 — 先用自制样本验证测试框架

可自行创作少量文本并构造最小HTML，明确标记synthetic：
- p与br正文；
- 正文和很长的评论区竞争；
- 一章两页、下一章独立；
- 两个目录页有重复边界；
- 倒序目录与分卷编号重置；
- 同页多个章节锚点；
- GBK/GB18030字节及HTTP/meta冲突；
- 403验证提示、200返回验证提示；
- 真正的短序章，不能只凭长度误判受限；
- 中断或部分失败时报告不完整，且不写伪正文。

这些测试只验证框架和规则，不计为20个真实站点已适配。

### D06 — 接入少量实际采样

- 先让用户指定或批准具体作品、页面范围及获取方式。
- 选择少量中文样本，保存采集输入并人工复核预期。
- 参考指南的P1顺序，但不能因为某站P1就盲目自动抓取。
- 受限/验证页面记录并停止；浏览器模式不是自动突破限制的后备方案。
- 未获公开许可或未完成隐私审查的输入放private，不推送GitHub。
- 原始HTML拿不到时只能保留候选或诊断记录，不能伪造HTTP快照。

### D07 — 冻结第一版数据与报告

- 按站点和模板家族分组，防止同站章节跨开发/最终测试集合。
- 标注coverage_plan中的真实已覆盖项，未覆盖项保持pending。
- 输出固定数据集版本的报告，先建立规则baseline。
- 不编造改善百分比、站点支持数量、编码覆盖率或测试执行记录。

## 完成后汇报

提供变更文件、实际执行命令、真实测试结果、现存缺口和下一步。
没有运行解析器时只能报告“配置校验通过”，不能报告“Benchmark通过”。
